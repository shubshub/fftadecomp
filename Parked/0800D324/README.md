# 0x0800D324

The recovered callback interleaves four 160-halfword planes into 160 eight-byte scanlines. Its ABI is `void (*)(void *state, u16 *destination)`. Scene 0x0811C018 calls 0x080D979C at 0x0811C11C with mode 2, BG 2 and horizontal coordinate 0. The child at 0x080D8E00 passes the mode to 0x0800CE08, which registers callback table slot 0x08149814, payload size 1280 and row width 8. The scanline manager at 0x0800C4B4 invokes the callback with the payload and inactive output bank.

The stock matcher verified 75/75 identical instructions and rejected the volatile qualifier. Removing the qualifier produces 120 bytes, SHA-256 `8addff6d0b57c58fbb7e0f3d8c198d76c3b0a307b5d0e21ae297f267f3443330`. Unqualified 16-bit bit-fields produced the same 120 bytes. Explicit byte stores produced 86 bytes.

Two-frame native instruction traces for each compiler form showed four halfword input loads and eight output-byte stores per row. Only the qualified form read each destination byte immediately before storing it. During the callback the DMA channel was disabled on the first frame and pointed at the opposite bank on the second. Both forms produced identical 1,288-byte banks including the repeated first row, identical BG2/BG3 row-zero shadows, and identical DMA source, destination and control registers. The later HBlank transfer consumes the stores. The existing evidence does not establish a hardware requirement for the 1,280 extra reads from the inactive EWRAM bank. No qualifier exception is proposed.
